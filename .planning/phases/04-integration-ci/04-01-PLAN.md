<decisions>
- Les règles s'évaluent sur le `Report` (donc après filtrage `--only` / `--exclude`) : filtrer le rapport restreint aussi ce qui est contrôlé.
- `Violation` porte une **empreinte stable** (`fingerprint`) qui ne dépend que de la règle et du sujet, jamais des valeurs mesurées : la baseline (04-02) en dépend. Formes : `no-cycles:class:A,B`, `no-cycles:component:X,Y` (membres triés), `stable-dependencies:From->To`, `max-distance:Component`.
- Une `Violation` a un `?string $file` (relatif à la racine) quand un fichier est pertinent (cycle de classes : fichier du premier membre), `null` sinon. Le SARIF (04-03) s'en servira.
- Le schéma JSON reste `1` : on ajoute une clé `violations` (toujours présente, tableau vide si aucune règle), ce qui est rétrocompatible.
- Aucune règle n'est active par défaut : sans `rules()`, le comportement de la phase 3 est inchangé (exit 0).
</decisions>

  <action>
    - `interface Rule { public function id(): string; public function description(): string; /** @return list<Violation> */ public function evaluate(Report $report): array; }`

    - `MaxDistanceFromMainSequence(max)` + `->for(string|list<string> $components)` (immuable, retourne une nouvelle instance ; sans `for`, tous les composants) : violation si `distance !== null && distance > max`.
    - `Violation` (`final readonly`) : `rule`, `fingerprint`, `message` (anglais, lisible, avec les valeurs mesurées arrondies à 2 décimales), `?file`.
    - Ajouter `string $file` à `ClassMetrics` (relatif à `basePath`) : le pipeline rend relatifs les fichiers des classes comme il le fait pour les `ParseError` (factoriser le calcul du chemin relatif). Mettre à jour le golden si besoin (`UPDATE_GOLDEN=1`, vérifier le diff).
  </action>
  <verify>Tests unitaires par règle sur des `Report` construits à la main : seuil et tolérance (strictement supérieur), `for()` immuable et restrictif, distance null ignorée, empreintes stables quand les valeurs changent, fichier du cycle de classes.</verify>
