<objective>
Ne reparser que les fichiers modifiés d'un run à l'autre, grâce à un cache des résultats de parsing indexé par empreinte de contenu.

Purpose : sur un gros projet, le parsing domine le temps d'exécution ; en CI comme en local, la plupart des fichiers ne changent pas.
Output : `CachedClassParser`, `ParseCache`, options `--no-cache` / `--clear-cache`, `Config::cache()`.
</objective>

<decisions>
- Décorateur du port : `CachedClassParser implements ClassParser` enveloppe le vrai parser. Le pipeline ne change pas.
- Clé d'une entrée : chemin absolu du fichier ; validité : `sha1` du contenu. L'en-tête du cache contient une **signature** (version de l'outil + version de php-parser + version du format de cache) : si elle change, tout le cache est ignoré.
- Stockage : un seul fichier `.dependencies-cache` à la racine (PHP `serialize` des `ParseResult`, écrit de façon atomique : fichier temporaire puis `rename`). Ajouté au `.gitignore`.
- Les entrées des fichiers non vus pendant le run sont supprimées à l'écriture (pas de croissance infinie).
- Cache **activé par défaut** ; `Config::cache(false)` ou `--no-cache` le désactivent ; `--clear-cache` supprime le fichier avant l'analyse.
- Un cache illisible ou corrompu n'est jamais une erreur : il est ignoré et réécrit.
</decisions>
