<decisions>
- Le fichier de config est du PHP qui **retourne** un `Config` : autocomplétion et validation par le typage, sans parser YAML/JSON.
- `Config` est immuable : chaque méthode retourne une nouvelle instance (`clone` + affectation via constructeur privé ou `with…`).
- Aucune règle (`rules()`) dans ce plan : elles arrivent en phase 4.
- Les options de la CLI priment sur la config ; la fusion se fait dans la commande (03-03), pas ici.
</decisions>

<tasks>

<task type="auto">
  <name>Task 1 : Config</name>
  <files>app/Core/Config/Config.php, tests/Core/Config/ConfigTest.php</files>
  <action>
    API publique (namespace `App\Core\Config`) :
    ```php
    Config::make(): self
    ->paths(list<string>): self            // dossiers/fichiers à analyser, relatifs à la racine
    ->exclude(list<string>): self          // globs de fichiers (SourceScanner)
    ->only(list<string>): self             // globs FQCN (Filter only)
    ->ignore(list<string>): self           // globs FQCN (Filter exclude)
    ->components(array<string, string|list<string>>): self
    ->componentDepth(int): self
    ->toOptions(string $basePath): AnalysisOptions
    ```
    Getters en lecture pour chaque valeur (utilisés par la commande pour fusionner avec la CLI). Valeurs par défaut : `paths = []`, `componentDepth = 2`, le reste vide.
    `toOptions()` lève `ConfigException` si `paths` est vide. La validation des composants vides et de la profondeur reste celle de `ComponentResolver` : `toOptions()` instancie un `ComponentResolver` à blanc pour la déclencher et convertit `InvalidArgumentException` en `ConfigException` (un seul endroit de validation).
  </action>
  <verify>Tests : builder immuable (l'instance d'origine ne change pas) ; `toOptions()` produit les bons `AnalysisOptions` (Filter only/exclude, composants, profondeur) ; `paths` vide → `ConfigException` ; composant vide → `ConfigException`.</verify>
  <done>Config immuable, validée, testée.</done>
</task>
